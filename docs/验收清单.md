# 功能验收指南

## 一、上传的文件存在哪里

**两个版本都只把"密文"写到磁盘，原始文件从不落盘。**

| 内容 | V1 对照版 | V2 目标版 |
| --- | --- | --- |
| 密文（每个文件一个） | `v1_server_key/data/blobs/<文件ID>.enc` | `v2_zero_knowledge/data/blobs/<文件ID>.enc` |
| 元数据 / 密钥 | `v1_server_key/data/v1.db` | `v2_zero_knowledge/data/v2.db` |
| 目录大小 | 随上传增长（Demo 全量约 3.4 MB） | 随上传增长（约 1.8 MB） |

要点：

1. **文件名是随机 ID**（`secrets.token_hex(8)`，如 `38ccccbde727c6d0.enc`），磁盘上看不出原文件名；原始文件名只记录在数据库里。
2. 密文大小 ≈ 原文件 + 16 字节（AES-GCM 认证标签）。
3. `data/` 目录已在 `.gitignore` 中排除，**不会进 Git 仓库**，也不会打进交付包；删掉它等于清空所有文件（重启服务会自动重建）。
4. V1 的 `files.key_b64` 就是解密密钥；V2 的 `files.wrapped_key_b64` 是用**公钥**封装过的密钥，没有私钥解不开。

```
v1_server_key/data/                   v2_zero_knowledge/data/
├── v1.db  ← 含 key_b64（明文密钥）     ├── v2.db  ← 只有公钥与 wrapped_key
└── blobs/                             └── blobs/
    ├── 38ccccbde727c6d0.enc               ├── 6a7f030c3a46ee01.enc
    └── ...                                └── ...
```

备份/迁移：直接拷 `data/` 整个目录即可（V1 拷过去仍可解密，V2 拷过去仍然解不开——这正好是演示点）。

## 二、一键验收（推荐）

先启动两个服务（`run_v1.bat` / `run_v2.bat`），然后：

```bash
python tests/acceptance_v1.py     # V1：8 种格式往返 + 权限 403 + 搭建者读库解密
node   tests/acceptance_v2.mjs    # V2：8 种格式往返 + 403 + 501 + 无机密字段 + 错口令
```

Windows 也可以双击 `tests/run_acceptance.bat`。

预期输出（V2 片段）：

```
文件                      类型         原始         密文   还原
--------------------------------------------------------------------
demo_code.js            代码     1.3 KB     1.3 KB   一致
...
演示视频.mp4             视频    1.56 MB    1.56 MB   一致
权限与自证
  PASS  小孔取密文被拒（403）
  PASS  服务端尝试解密返回 501  → NO_PRIVATE_KEY
  PASS  数据库无任何机密字段  → secret_columns=[]
  PASS  错误口令无法解开密钥包
```

更细的边界测试（篡改密文、他人私钥、错误口令等）另有两套：

```bash
python tests/e2e_v1.py     # 9 项
node   tests/e2e_v2.mjs    # 10 项
```

### D. V2 目标版（搭建者无法解密）

| # | 操作 | 预期 |
| --- | --- | --- |
| D1 | 小张点「生成密钥对」 | 自动下载 `小张-私钥包-日期.key.json`；页面显示公钥指纹 |
| D2 | 查看 V2 数据库 `files` 表 | 没有 `key`/`private_key` 字段，只有 `wrapped_key_b64` |
| D3 | 点「让服务端试着解密最新文件」 | HTTP **501**，`reason=NO_PRIVATE_KEY` |
| D4 | 点「查看数据库表结构」 | 所有字段 `holds_secret=false`，`secret_columns=[]` |

## 四、常见问题

- **页面看不到上传的文件**：确认打开的是同一个 `data/` 目录对应的服务；删过 `data/` 会清空。
- **V2 点加密提示"还没有公钥"**：先用小张登录生成密钥对（公钥是加密的前提）。
- **V2 解密失败**：确认密钥包与当前公钥是同一对（重新生成过密钥对会导致旧文件解不开）。
- **公网访问时页面报 crypto.subtle undefined**：Web Crypto 只在 HTTPS 或 localhost 下可用，需配置 TLS。
