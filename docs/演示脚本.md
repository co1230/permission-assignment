# 现场演示脚本（约 10 分钟）

## 准备（演示前 5 分钟）

1. 启动两个服务：

   ```
   v1_server_key\run_v1.bat     → http://127.0.0.1:8001
   v2_zero_knowledge\run_v2.bat → http://127.0.0.1:8002
   ```

2. （可选）清空历史数据，从零演示：删除 `v1_server_key\data` 与 `v2_zero_knowledge\data` 后重启。
3. 准备好 `test_files/` 里的 8 个测试文件（md / py / js / docx / xlsx / pdf / mp3 / mp4）。

账号：小孔 `xiaokong / xiaokong123`（只能加密）；小张 `xiaozhang / xiaozhang123`（可解密）。

---

## 第一幕 · V1 对照版（约 3 分钟）

1. 打开 `http://127.0.0.1:8001`，用 **小孔** 登录。
2. 上传 `项目说明.md` 和 `演示视频.mp4`，指出类型自动识别、密文大小。
3. 表格里的"解密下载"对 小孔 是灰的 → 点了也不会有权限（服务端 403）。
4. 退出，换 **小张** 登录：同一批文件现在可以"解密下载"，下载的 MP4 能直接播放。
5. **关键镜头**：拉到下方「服务端密钥库」——每个文件对应的 AES 密钥明晃晃地写在页面上，而它来自数据库。
6. 收尾一句话："V1 里，小孔解不开只是因为接口拦他；任何能碰服务器的人——包括搭建这个系统的我——都能解开一切。"

## 第二幕 · V2 目标版（约 5 分钟）

1. 打开 `http://127.0.0.1:8002`，用 **小张** 登录。
2. 「我的密钥包」→ 生成密钥对 → 设置口令（现场输入，例如一串只有你知道的字符）→ 私钥包 `.key.json` 自动下载。
   强调：**这个文件只存在你的电脑上，服务器只收到了公钥。**
3. 退出，换 **小孔** 登录。上传 `测试音频.mp3`、`demo_code.py`——页面会显示"本地加密中… → 上传密文中…"。
   讲解：加密发生在浏览器，服务端只见到密文和被公钥封装的密钥。
4. 小孔视角：解密按钮是灰的（他既没有私钥，服务端也不会给他密文）。
5. 退出，换回 **小张**：
   - 「我的私钥」→ 选择刚下载的密钥包 → 输入口令 → "私钥已解锁"；
   - 文件列表点「本地解密」→ 音频下载后直接播放，代码文件打开看注释是否完好。
6. **杀手锏镜头**：「服务器自证：它解不开」→ 点"让服务端试着解密最新文件"：
   返回 **HTTP 501 / NO_PRIVATE_KEY**，服务端列出了自己有什么、缺什么。
   再点"查看数据库表结构"：所有字段里没有任何机密列。
7. **可选加分镜头**：故意输错口令解锁 → 被拒；用"下载密文 + 封装信息"走一遍「离线解密」，说明解密根本不需要服务器在线。

## 第三幕 · 结论（约 1 分钟）

- V1：加密保护的是"传输和存储被偷看"，防不住服务端自己。
- V2：解密材料只存在于密钥持有者的设备上。搭建者拥有 root、数据库、磁盘，唯一缺的东西是 **私钥**——而这正是设计使然。
- 现场对比两版数据库：`v1_server_key/data/v1.db` 有 `key_b64` 列；`v2_zero_knowledge/data/v2.db` 没有。

## 常见提问应答

**Q：搭建者会不会在代码里留后门？**
V2 的密码学逻辑全部在 `v2_zero_knowledge/static/crypto-core.js`，约 200 行，可公开审计；私钥的生成、封装、解封只调用浏览器原生 Web Crypto，代码里没有任何把私钥或口令发往服务器的语句（可抓包验证）。

**Q：小张的私钥包丢了怎么办？**
文件丢了但没口令 → 别人捡到也解不开；文件和口令都丢了 → 该密钥对加密的旧文件永久无法解密（这是零知识的代价，文档"已知边界"一节有说明）。

**Q：为什么不用更复杂的方案？**
AES-GCM + RSA-OAEP 是业界标准组合（PGP/KMS 同款思路），演示版刻意保持"每个环节都能被看懂"。

**Q：测试文件怎么证明没损坏？**
对比 SHA-256。`test_files/项目说明.md` 里有现成的对比命令。
